    DNS en local¶

    Se trata de resolver direcciones de dominios a la dirección de host local 127.0.0.xxx. Esto permitirá trabajar en un entorno local.

    Para ello dispone de varias aproximaciones:

    1. Modificar /etc/hosts
    2. Usar el dominio .localhost
    3. usar un gestor de dominios y redirigir a 127.0.0.xxx

    Info

    En otro apartado se usaran direcciones IP públicas con una instancia EC2 de AWS.

    1. Primera aproximación: /etc/hosts¶

    Lo más sencillo para hacer pruebas en local es modificar el fichero /etc/hosts. Tenga en cuenta que para resolver la IP de un nombre de host se consulta primero el fichero /etc/hosts y si no hay correspondencia se consulta a los servidores DNS.

    Se puede asociar en ese fichero el nombre de un dominio (por ejemplowhoami.md.internal) a la dirección local 127.0.0.1 y podría usar ese nombre en sus pruebas en local con el navegador, etc.

    $ sudo nano /etc/hosts
$ cat /etc/hosts
127.0.0.1       whoami.md.internal localhost
127.0.1.1       xd13
...
$

    Puede probar la resolución del nombre a IP:

    $ getent hosts test.md.internal
127.0.0.1       test.md.internal localhost
$ ping -c 3 test.md.internal
PING test.md.internal (127.0.0.1) 56(84) bytes of data.
64 bytes from test.md.internal (127.0.0.1): icmp_seq=1 ttl=64 time=0.027 ms
...
3 packets transmitted, 3 received, 0% packet loss,
~$

    Esta solución puede ser suficiente para el desarrollo de prácticas en local.

    2. El dominio .locallhost¶

    ¿Y si no tuviera permisos para modificar el fichero /etc/hosts? En ese caso se puede utilizar el "dominio" .localhost que resuelve por defecto a 127.0.0.1.

    Observe un ejemplo con el dominio sitio1.localhost. Si tiene funcionado un servidor web

    docker run -d -p 80:80 nginx

    La petición usando el nombre del dominio

    $ curl sitio1.localhost
<!DOCTYPE html>
<html>
...
<h1>Welcome to nginx!</h1>
...
</html>
$

    O si hace la petición a un subdominio

    $ curl --head app.sitio1.localhost
HTTP/1.1 200 OK
Server: nginx/1.31.6
...
Accept-Ranges: bytes
$

    Tenga en cuenta que es algo "interno" y no es una resolución de host a IP (que sí lo era en el apartado previo)

    $ ping app.sitio1.localhost
ping: app.sitio1.localhost: Nombre o servicio desconocido
$

    Esta solución podría también ser suficiente para el desarrollo de prácticas en local.

    3. Usando un dominio registrado¶

    Esta tercera opción pretende usar un gestor de dominios para mapear el nombre de dominio a la dirección local 127.0.0.xxx

    3.1. Dominios gratuitos¶

    Primero necesita conseguir un nombre de dominio para su IP sin coste. Hay varias opciones que se muestran en el anexo, entre ellas:

    • Freemyip: https://freemyip.com/
    • Dynu: https://www.dynu.com/en-US/
    • Duck DNS: https://duckdns.org.
    • El dominio .tech es gratuito usando el Developer Pack Student de GitHub.

    3.2. Usando un gestor DNS gratuito: freemyip¶

    En este ejemplo usaremos freemyip, que no requiere crear una cuenta y proporciona un token asociado al nombre de dominio para su gestión. Además, sus subdominios heredan la IP de forma que por ejemplo

    midominio.freemyip.com
whoami.midominio.freemyip.com
app1.midominio.freemyip.com
wordpress.midominio.freemyip.com

    pueden resolver todos a la misma dirección.

    3.3. Registro en freemyip¶

    Sobre el acceso a freemyip desde el aula

    freemyip puede establecer límites si detecta muchas peticiones desde la misma IP, que es lo que ocurre normalmente desde un aula.

    Para evitarlo se recomienda:

    • usar el navegador
    • instalar un plugin de VPN y activarlo antes
    • hacer las peticiones en el navegador en vez de con curl.

    Tiene información sobre plugins de VPN en los anexos.

    Observe la página inicial dónde puede especificar el nombre deseado:

    y si está libre nos lo indica y da la oprtunidad de solicitarlo usando el botón CLAIM IT!

    Finalmente si todo es correcto nos indica la URL para actualizar al IP, que incluye el token para la gestión y el nombre del dominio. Es importante no perder ese token porque no hay forma de recuperarlo y se pierde el dominio.

    Por defecto se asocia el dominio a la IP desde que se ha realizado la petición. Si desea comprobar:

    clases@d13:~$ dig +short midominio.freemyip.com
82.40.155.129
clases@d13:~$ dig +short app.midominio.freemyip.com
83.40.155.129
clases@d13:~$

    freemyip permite gestionar el dominio creado mediante peticiones URL. Tiene los detalles en su ayuda.

    3.4. Resolviendo el nombre de dominio a 127.0.0.x¶

    Esto es una "solución" para el caso de pruebas en local que requieran de resolución de nombres "reales" y no desea utilizar las soluciones anteriores de modificar el fichero /etc/hosts * o usar el dominio .localhost,

    freemyip gestiona el dominio creado mediante peticiones URL que incluyan el token y el domain. Una de las posibilidades es especificar la IP que desea asociar al dominio usando además el parámetro myip en la URL.

    El formato sería:

    "https://freemyip.com/update?token=TOKEN&domain=DOMINIO&myip=NUEVAIP&verbose=yes"

    Si desea asociar el dominio a su dirección de localhost puede usar como ip 127.0.0.1(es posible que la .1 porovoque un error y tenga que usar la .2, etc).

    firefox \
  "https://freemyip.com/update?token=TOKEN&domain=DOMINIO&myip=127.0.0.2&verbose=yes"
# o en CLI
curl \ 
  "https://freemyip.com/update?token=TOKEN&domain=DOMINIO&myip=127.0.0.2&verbose=yes"

    Uso de comillas en la URL

    Es necesario e importante delimitar la URL con comillas.

    Para comprobar el resultado use dig:

    dig +short midominio.freemyip.com
dig +short whoami.midominio.freemyip.com

    y debería obtener la IP de localhost.

    Warning

    Si accede a la API sin especificar el campo myip se entiende que la IP a utilizar es la del equipo desde que hace la consulta y se pierde la anterior.

    Lo mismo ocurre si intenta modificar la IP y no delimita la URL con comillas.

    4. Anexo freemyip¶

    4.1. Resolviendo a IP públicas¶

    El procedimento es similar: basta indicar en la URL la IP de su servidor externo o instancia AWS EC2. Tenga encuenta que la IP de las instancias AWS EC2 de los laboratorios cambia (a no ser que use IP elástica).

    firefox \
  "https://freemyip.com/update?token=TOKEN&domain=DOMINIO&myip=IP&verbose=yes"
# o desde CLI
curl |
  "https://freemyip.com/update?token=TOKEN&domain=DOMINIO&myip=IP&verbose=yes"

    4.2. Añadir registro TXT en el dominio¶

    Puede ser en algún momento necesario añadir un registro TXT asociado al dominio (por ejemplo nos pueden solicitar añadirlo un registro TXT con un texto determinado para demostrar que ser propietario del dominio).

    You can use an optional "&txt" parameter to do that. This will also automagically work for any subdomain within your domain. If you want to remove your TXT record, use "&txt=null" or "&txt=". You can also add parameter "&verbose=yes" to see some more information in the output, especially if you encounter an error. Any time you change your TXT record, you will have to wait around 1 minute for DNS cache to get updated.

    Algo similar a

     "https://freemyip.com/update?token=TOKEN6&domain=DOMINIO&txt=texto&verbose=yes"

    5.1. Duckdns¶

    https://duckdns.org

    La principal diferencia con FreeMyIp es que necesita registro para obtener el dominio y el token asociado. Una vez obtenidos su API ofrece un funcionamiento similar.

    LA URL necesaria sería similar a 

    curl \
"https://www.duckdns.org/update?domains=${DOMAIN}&token=${TOKEN}&ip=${IP}&verbose=true"

    If you do not specify the IP address, then it will be detected - this only works for IPv4 addresses

    5.2. Dominio en Dynu¶

    Puede darse de alta en https://www.dynu.com/en-US/

    5.2.1. Dominio DDNS¶

    Puede añadir un dominio en el menú DDNS, opción SIGN UP. Este debería ser el enlace:

    https://www.dynu.com/en-US/ControlPanel/AddDDNS

    Debe usar la opción Option 1: Use Our Domain Name, seleccionar uno de sus dominios en el desplegable y elegir un Nombre de Host. Luego pulsar el botón Add

    Una vez creado le muestra el dominio y observe que de formaautomática le ha asignado una IP a ese dominio. Esa IP es la del equipo del que se está conectando, y lo habitual es que sea la IP pública del router de la red desde la que se esté conectando en ese momento.

    Importante:

    • Esa IPv4 Address será la que deberá sustitutir por la IP Elásctica de su instancia EC2.
    • Observe que tiene activo por defecto las Wirldcard IPv4 alias, por lo que cualquier nombre que termine en .daweb.freedns.org como whoami.daweb.freedns.org o www.daweb.freedns.org resuelve la misma IP.
    • Puede acceder a la gestión en detalle tiene a la derecha la opción DNS Records.

    5.3. dominio en .tech¶

    El dominio .tech es gratuito usando el Developer Pack Student de GitHub. En este caso tenga en cuenta que:

    1. Importante: debe realizar el alta desde esta dirección: https://get.tech/github-student-developer-pack.
    2. Buscar y seleccionar un dominio libre
    3. Al ordenar el pago hay un botón para identificarse con su cuenta de GitHub (la que esté asociada a los beneficios del github student developer pack). Al usar esa opción el coste del dominio debe ser gratuito durante un año.
    4. Para gestionar el dominio acceda a http://controlpanel.tech/customer.
