    Docker y servidores de aplicaciones¶

    Hasta ahora hemos servido archivos estáticos con Apache y desplegado sistemas de bases de datos. Un servidor de aplicaciones permite ejecutar lógica del lado del servidor. En este ejemplo usaremos Apache Tomcat para ejecutar una pequeña aplicación Java basada en JSP.

    1. ¿Qué es un servidor de aplicaciones?¶

    Un servidor de aplicaciones proporciona un entorno para ejecutar código del lado del servidor y atender peticiones de clientes. Puede incorporar gestión de sesiones, conexiones, autenticación y otros servicios, aunque las funciones concretas dependen del producto.

    Ejemplos del ecosistema Java:

    • Apache Tomcat: contenedor de servlets y motor JSP; no es un servidor Jakarta EE completo.
    • WildFly: servidor de aplicaciones Jakarta EE.
    • GlassFish / Payara: plataformas Jakarta EE.
    • Jetty: servidor HTTP y contenedor de servlets.

    Apache HTTP Server no es Apache Tomcat

    Ambos proyectos son de la Apache Software Foundation, pero tienen cometidos diferentes. Apache HTTP Server destaca al servir contenido web y actuar como proxy. Tomcat ejecuta aplicaciones Java web como servlets y JSP. Una arquitectura real puede combinarlos, pero no es necesario hacerlo en esta práctica.

    2. Apache Tomcat¶

    Tomcat es un servidor open source desarrollado por la Apache Software Foundation. Implementa las especificaciones Servle y JSP.

    Características principales:

    • Ligero y fácil de configurar.
    • Ideal para desplegar aplicaciones Java web (archivos .war).
    • Se puede ejecutar como servicio o en contenedor Docker.
    • Accesible por defecto en el puerto 8080.

    3. Apache Tomcat y archivos WAR¶

    Un archivo WAR (Web Application Archive) empaqueta una aplicación web Java. Tomcat suele desplegar los WAR colocados en el directorio /usr/local/tomcat/webapps/ de la imagen oficial. ROOT.war se despliega como aplicación raíz, accesible en /.

    Usaremos tomcat:10.1-jdk17, que proporciona Tomcat 10.1 con Java 17 y utiliza la familia de APIs Jakarta.

    Requisitos

    • Docker Engine y docker compose funcionando.
    • Un archivo WAR compatible con Tomcat 10.1.
    • La herramienta jar para empaquetar archivos (forma parte de un JDK). Comprueba su disponibilidad mediante jar --version.

    4. Preparar una aplicación JSP de ejemplo¶

    Pepararemos un ejemplo mínimo de aplicación JSP

    mkdir -p tomcat-docker/app
cd tomcat-docker

    Crea app/index.jsp:

    app/index.jsp

    Construye el fichero WAR en el directorio raíz del proyecto:

    tomcat-docker$ jar --create --file app.war -C app .
tomcat-docker$ jar --list --file app.war
META-INF/
META-INF/MANIFEST.MF
index.jsp
tomcat-docker$

    Comando jar no encontrado

    El comando jar no viene incluido en el entorno de ejecución básico (JRE), sino que requiere el kit de desarrollo (JDK). Se instala desde la terminal con: 

    sudo apt update
sudo apt install default-jdk

    5. Crear una imagen propia de Tomcat¶

    Cree este Dockerfile en tomcat-docker:

    Dockerfile
    1
2
3
    FROM tomcat:10.1-jdk17
COPY ./app.war /usr/local/tomcat/webapps/ROOT.war
EXPOSE 8080

    EXPOSE documenta el puerto que utiliza el servicio dentro del contenedor, pero no publica por sí mismo el puerto en el anfitrión. Eso se hará con -p o con ports en Compose.

    Construya y ejecute:

    docker build -t tomcat-aula:1.0 .
docker run -d --name tomcat-app \
  -p 8080:8080 \
  tomcat-aula:1.0

    Comprueba el despliegue:

    docker logs -f tomcat-app

    Pulsa Ctrl+C para dejar de seguir los registros y abre http://localhost:8080/. La primera petición puede tardar unos instantes mientras se despliega el WAR y se compila el JSP.

    Pruebe el acceso desde el navegador (y compruebe que el fichero .war está en su localziación)

    curl http://localhost:8080/
docker exec tomcat-app ls /usr/local/tomcat/webapps/

    ¿No aparece la aplicación?

    Revisa si el WAR se ha desplegado correctamente, si el archivo se llama ROOT.war y si la aplicación es compatible con Tomcat 10.1. Una respuesta HTTP 404 puede significar que la aplicación aún no se ha desplegado, que su ruta es diferente o que ha fallado durante el arranque.

    7. Anexo: Práctica con aplicación adivina¶

    7.1. La aplicación¶

    Crear un directorio:

    mkdir tomcat-docker
cd tomcat-docker

    Se le proporciona en este ejemplo una aplicacion desarrolada en JSP que solicita que el usuario adivine un nombre. Este es el fichero que debe descargar:

    Fichero guess-number.zip

    Ahora basta descomprimir y crear el fichero war:

    unzip guess-number.zip
cd guess-number
jar cvf guess-number.war  *.jsp

    7.2. Crear la imagen¶

    Usar un Dockerfile similar a este que debe almacenar en la carpeta tomcat-docker

    Dockerfile

    # Usar la imagen oficial de Tomcat
FROM tomcat
# FROM tomcat:10-jdk17

# Copiar nuestra app al directorio webapps
COPY ./guess-number/guess-number.war /usr/local/tomcat/webapps/ROOT.war

# Exponer el puerto 8080
EXPOSE 8080

    Y construir la imagen

    docker build -t mitomcat-app .

    7.3. Probarla¶

    Ejecuta en tu terminal

    docker run -d -p 8080:8080 --name tomcat-app mitomcat-app

firefox http://localhost:8080

    Deberías ver la aplicación Java funcionando dentro del contenedor Tomcat.

    7.4 Con compose¶

    En este caso no se crea una imagen sino que se usa la de tomcat, y un volumen para la aplicación. Usar un compose similar a este:

    compose.yaml

    services:
  tomcat:
    image: tomcat
    container_name: mitomcat
    ports:
      - "8080:8080"
    volumes:
      - ./guess-number/guess-number.war:/usr/local/tomcat/webapps/ROOT.war
    restart: unless-stopped

    Y para ejecutar

    docker compose up -d
