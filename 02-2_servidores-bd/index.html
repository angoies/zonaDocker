    Docker y bases de datos¶

    Docker permite ejecutar sistemas gestores de bases de datos sin instalarlos directamente en el sistema operativo. Empezaremos con MySQL y continuaremos con PostgreSQL, Adminer, volúmenes y scripts de inicialización.

    Credenciales de laboratorio

    Las contraseñas de los ejemplos se usan solo en entornos locales de aprendizaje. No debes subir contraseñas reales a repositorios públicos ni reutilizarlas en un servidor de producción. No publiques los puertos de las bases de datos si no necesitas acceder directamente desde el anfitrión.

    1. MySQL desde la línea de comandos¶

    Las imágenes oficiales permiten configurar la base de datos por variables de entorno. Por ejemplo, MYSQL_ROOT_PASSWORD configura la contraseña inicial de root. En este ejemplo inicial se utilizará la variable de entorno MYSQL_ROOT_PASSWORD para indicarle al contenedor la clave del usuario root.

    Si usa la linea de comandos las variables de entorno se pasan con la opción -e, en este caso -e MYSQL_ROOT_PASSWORD=miclave. 

    docker run -d --name mibd \
  -e MYSQL_ROOT_PASSWORD=clave-aula \
  mysql:8.4

    Observe que en este caso no se publica el puerto 3306: para administrarla desde dentro del contenedor no es necesario. La inicialización puede tardar unos segundos:

    docker ps
docker

    Para comprobar que la BD está operativa acceda directamente al cliente de MySQL del contenedor con docker exec:

    $ docker exec -it mibd mysql -u root -p

    2. MySQL con Docker Compose y persistencia¶

    Puede crear un fichero compose y en este caso pasar la información de las variables de entorno y el uso de un volumen apra dar persistencai a los datos.

    compose.yaml

    services:
  db:
    image: mysql:8.4
    environment:
      MYSQL_ROOT_PASSWORD: clave-aula
      MYSQL_DATABASE: aula
      MYSQL_USER: alumno
      MYSQL_PASSWORD: clave-alumno
    volumes:
      - mysql_datos:/var/lib/mysql
    restart: unless-stopped

volumes:
  mysql_datos:
    • db es el nombre del servicio y también se utiliza como nombre DNS en la red del proyecto.
    • environment define los valores empleados al inicializar la base de datos por primera vez, usuario y clave.
    • mysql_datos es un volumen con nombre administrado por Docker.
    • /var/lib/mysql es el directorio de datos de la imagen MySQL.

    Puede ejecutar los comandos para despelgar y comprobar:

    docker compose config
docker compose up -d
docker compose ps
docker compose logs -f db

    Pulsa Ctrl+C para salir del seguimiento de los logs sin detener el servicio.

    Las bases de datos pueden tardar unso segundos en estar oeprativas. Cuando MySQL esté listo puede eejcutar el clietne mysql en el conteendor:

    docker compose exec db mysql -u alumno -p aula

    Introduce clave-alumno y crea una tabla de prueba:

    2.1. Comprobar la persistencia¶

    docker compose down
docker volume ls
docker compose up -d
docker compose exec db mysql -u alumno -p aula

    Una vez conectado:

    SELECT * FROM mensajes;

    El registro sigue ahí porque docker compose down no borra por defecto los volúmenes con nombre.

    ¡Cuidado con down -v!

    docker compose down -v elimina también los volúmenes declarados en el proyecto (y los anónimos asociados). En una práctica que utiliza datos de prueba puede servir para reiniciar el ejercicio, pero ocasiona pérdida de datos. No lo ejecutes sobre proyectos con información que quieras conservar.

    Variables de inicialización

    Cambiar MYSQL_DATABASE, MYSQL_USER o las contraseñas en el YAML no modifica automáticamente una base de datos ya inicializada dentro del volumen. Esas variables se aplican principalmente cuando el directorio de datos está vacío. Para modificar usuarios o contraseñas existentes debes utilizar SQL y los procedimientos correspondientes.

    3. Añadir una interfaz web: Adminer¶

    Adminer permite administrar varias bases de datos desde el navegador. Añade este servicio dentro del bloque services del Compose anterior:

    Fragmento para añadir a compose.yaml
    1
2
3
4
5
6
7
      adminer:
    image: adminer:5
    ports:
      - 8080:8080
    depends_on:
      - db
    restart: unless-stopped

    Arranca los servicios:

    docker compose up -d

    Abre http://localhost:8080/. Para MySQL utiliza:

    Campo de Adminer Valor
    Sistema MySQL
    Servidor db
    Usuario alumno
    Contraseña clave-alumno
    Base de datos aula

    ¿Por qué el servidor se llama db y no localhost?

    Adminer se ejecuta dentro de otro contenedor. Allí, localhost significa el propio Adminer. Como ambos servicios pertenecen al mismo proyecto Compose, Docker permite alcanzar MySQL mediante db:3306. Desde el anfitrión, el navegador accede a Adminer en localhost:8082. Son conexiones distintas.

    depend_on

    depends_on en su forma básica ordena el arranque, pero no garantiza que la base de datos ya acepte conexiones. Si el primer intento falla, consulta docker compose logs db, espera a que termine la inicialización y vuelve a probar.

    3.1. ¿Es necesario publicar el puerto de MySQL?¶

    No: Adminer y MySQL comparten la red de Compose y pueden comunicarse sin ports en db. Si necesitas conectarte desde una herramienta instalada en el ordenador anfitrión, puedes añadir opcionalmente:

        ports:
      - "127.0.0.1:3307:3306"

    Este fragmento va dentro del servicio db: el cliente del anfitrión usará 127.0.0.1:3307, mientras que Adminer seguirá usando db:3306.

    4. Inicializar una base de datos mediante SQL¶

    La imagen oficial MySQL ejecuta los scripts colocados en /docker-entrypoint-initdb.d/ durante la inicialización de un directorio de datos vacío. En mysql-aula crea sql/01_datos.sql:

    sql/01_datos.sql
    1
2
3
4
5
6
7
8
    USE aula;
CREATE TABLE IF NOT EXISTS productos (
  id INT AUTO_INCREMENT PRIMARY KEY,
  nombre VARCHAR(80) NOT NULL,
  precio DECIMAL(8,2) NOT NULL
);
INSERT INTO productos (nombre, precio)
VALUES ('Teclado', 19.90), ('Ratón', 12.50);

    Añade un segundo montaje a db:

        volumes:
      - mysql_datos:/var/lib/mysql
      - ./sql:/docker-entrypoint-initdb.d:ro

    No se ejecuta en cada arranque

    Si el volumen ya contiene una base de datos inicializada, los scripts no volverán a ejecutarse, aunque cambies su contenido. Para hacer una prueba limpia puedes borrar los volúmenes con docker compose down -v, solo después de comprobar que no necesitas conservar los datos. Una alternativa no destructiva es crear un proyecto nuevo con otro nombre y volumen.

    6. Diagnóstico y operaciones útiles¶

    docker compose ps -a                 # Estado de los servicios
docker compose logs --tail=50 db     # Últimos registros de la BD
docker compose exec db env           # Variables visibles en el contenedor
docker volume ls                     # Volúmenes existentes
docker compose config                # Configuración interpretada
    Problema Explicación probable
    Adminer no puede resolver localhost como BD Debe utilizarse db, no localhost
    «Connection refused» al primer acceso El SGBD aún está inicializándose o no está listo
    Cambié una contraseña y no funciona El volumen existente conserva los usuarios iniciales
    El SQL no se ejecuta tras reiniciar Los scripts de inicialización solo se procesan con el directorio de datos vacío
    Error al publicar un puerto Ya está ocupado; cambia el puerto del anfitrión
