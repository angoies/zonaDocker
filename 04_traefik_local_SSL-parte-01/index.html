    HTTPS local con Traefik¶

    En esta práctica vamos a configurar Traefik como reverse proxy para publicar varios servicios Docker mediante HTTPS utilizando certificados públicos de Let's Encrypt.

    La particularidad del montaje es que los servicios no estarán expuestos a Internet. Utilizaremos un dominio gratuito de FreeMyIP que resolverá a:

    127.0.0.1

    De esta forma, nombres como:

    whoami.mi-dominio.freemyip.com
nginx.mi-dominio.freemyip.com

    apuntarán al propio ordenador desde el que se realiza la práctica.

    Para demostrar a Let's Encrypt que controlamos el dominio utilizaremos el desafío DNS-01. Traefik modificará temporalmente registros DNS de tipo TXT mediante la API de FreeMyIP. La arquitectura será aproximadamente la siguiente:

                             Internet
                            │
                            │ consulta DNS TXT
                            ▼
                    ┌────────────────┐
                    │   FreeMyIP     │
                    │   DNS público  │
                    └───────▲────────┘
                            │
                         DNS-01
                            │
                  ┌─────────┴─────────┐
                  │     Traefik       │
                  │   ACME + lego     │
                  └─────────▲─────────┘
                            │
                            │ ACME
                            ▼
                    ┌────────────────┐
                    │ Let's Encrypt  │
                    │      CA        │
                    └────────────────┘


Navegador
    │
    │ https://whoami.mi-dominio.freemyip.com
    │
    ▼
127.0.0.1:443
    │
    ▼
┌───────────────┐
│    Traefik    │
└───────┬───────┘
        │
        ├──────────► whoami
        │
        └──────────► nginx

    Idea fundamental

    Let's Encrypt no necesita conectarse a los puertos 80 o 443 del equipo cuando utilizamos DNS-01. La validación se realiza consultando un registro DNS de tipo TXT.

    Al finalizar la práctica deberás ser capaz de:

    • configurar Traefik como reverse proxy de varios contenedores.
    • utilizar nombres DNS reales para acceder a servicios locales.
    • utilizar FreeMyIP como proveedor DNS.
    • obtener certificados TLS mediante Let's Encrypt.
    • utilizar el entorno de pruebas (staging) de Let's Encrypt.
    • comprobar certificados mediante openssl.
    • observar la resolución DNS mediante dig.

    Debes disponer de:

    • Docker y Docker Compose.
    • curl y dig (normalmente incluido en el paquete dnsutils).
    • openssl.

    1. Preparación dominio¶

    1.1. Crear dominio FreeMyIP¶

    Accede a FreeMyIP y crea un nombre gratuito. Por ejemplo alumno01.freemyip.com. A partir de ahora utilizaremos como ejemplo el dominio alumno01.freemyip.com Sustituye este valor por tu propio dominio.

    FreeMyIP proporcionará un token asociado al dominio.

    El token es una credencial

    El token permite modificar información DNS asociada al dominio. No debes: - publicarlo. - incluirlo en capturas de pantalla. - subirlo a Git. - compartirlo con otros alumnos.

    Normalmente un servicio de DNS dinámico se utiliza para apuntar a una IP pública. En nuestro caso queremos exactamente lo contrario: queremos que el dominio apunte al propio equipo. La dirección 127.0.0.1 es la dirección de loopback, por tanto:

    alumno01.freemyip.com
        │
        ▼
    127.0.0.1

    y cualquier subdominio whoami.alumno01.freemyip.com o nginx.alumno01.freemyip.com también resolverá hacia el equipo local.

    1.2. Fichero .env¶

    Crea el directorio del proyecto:

    mkdir traefik-dns01
cd traefik-dns01

    Crea el fichero:

    .env

    con el siguiente contenido:

    DOMAIN=alumno01.freemyip.com
FREEMYIP_TOKEN=TU_TOKEN
LE_EMAIL=tu_correo@example.com

    Sustituye con tus propios datos y protege el fichero:

    chmod 600 .env

    1.3. Actualizar FreeMyIP¶

    Carga las variables:

    set -a
source .env
set +a
echo $DOMAIN $FREEMYIP_TOKEN

    Info

    Activa la exportación automática, carga las variables y las exporta y desactiva la exportación automática (conserva las variables cargadas). Esas variables están ahora disponibles para comandos o scripts que ejecutemos desde nuestra shell.

    Y ahora actualiza el dominio:

    curl "https://freemyip.com/update?token=${FREEMYIP_TOKEN}&domain=${DOMAIN}&myip=127.0.0.1&verbose=yes"

    FreeMyIP debería responder indicando que la actualización se ha realizado correctamente.

    Note

    Utilizar variables evita escribir el token directamente en el comando guardado en el historial del shell.

    Note

    Si sólo quiere tener disponibles estas variables para el fichero compose.yml no es encesario exportarlas, compose las lee automáticamente del fichero .env

    Warning

    Es posible que se genere un error al usar la IP 127.0.0.1, Pruebe con otra del rango 127.0.0.X

    Para comprobar la resolución DNS

    $ dig +short ${DOMAIN}
127.0.0.1

    Ahora prueba un subdominio que todavía no existe como servicio:

    $dig +short whoami.${DOMAIN}
127.0.0.1

    FreeMyIP hace que los subdominios del nombre asignado resuelvan a la misma dirección IP. Por tanto:

    alumno01.freemyip.com
whoami.alumno01.freemyip.com
nginx.alumno01.freemyip.com
apache.alumno01.freemyip.com

    pueden resolver todos a 127.0.0.1. Esto permite utilizar Traefik para decidir qué contenedor debe responder dependiendo del nombre solicitado.

    2. Traefik y HTTPS¶

    El proyecto tendrá inicialmente esta estructura:

    traefik-dns01/
├── .env
├── .gitignore
├── compose.yml
└── letsencrypt/
    └── acme.json

    Crea el directorio y el fichero de almacenamiento de ACME:

    mkdir -p letsencrypt
touch letsencrypt/acme.json
chmod 600 letsencrypt/acme.json

    Crea .gitignore con:

    .env
letsencrypt/acme.json

    Warning

    acme.json contiene información sensible relacionada con la cuenta ACME y los certificados. No debe publicarse en un repositorio.

    3. Primer servicio¶

    3.1. compose.yml inicial¶

    Crea compose.yml con el siguiente contenido:

    services:

  traefik:
    image: traefik:v3.7

    command:
      # API y dashboard para el entorno de prácticas
      - "--api.insecure=true"

      # Proveedor Docker
      - "--providers.docker=true"
      - "--providers.docker.exposedbydefault=false"

      # Puntos de entrada
      - "--entrypoints.web.address=:80"
      - "--entrypoints.websecure.address=:443"

      # Redirección HTTP -> HTTPS
      - "--entrypoints.web.http.redirections.entrypoint.to=websecure"
      - "--entrypoints.web.http.redirections.entrypoint.scheme=https"

      # Resolver ACME
      - "--certificatesresolvers.le.acme.email=${LE_EMAIL}"
      - "--certificatesresolvers.le.acme.storage=/letsencrypt/acme.json"

      # Desafío DNS-01
      - "--certificatesresolvers.le.acme.dnschallenge=true"
      - "--certificatesresolvers.le.acme.dnschallenge.provider=freemyip"

      # DNS utilizados por Traefik para comprobar la propagación
      - "--certificatesresolvers.le.acme.dnschallenge.resolvers=1.1.1.1:53,8.8.8.8:53"

      # Entorno de pruebas de Let's Encrypt
      - "--certificatesresolvers.le.acme.caserver=https://acme-staging-v02.api.letsencrypt.org/directory"

      # Logs
      - "--log.level=INFO"

    environment:
      - FREEMYIP_TOKEN=${FREEMYIP_TOKEN}

    ports:
      - "80:80"      # "127.0.0.1:80:80"
      - "443:443"    # "127.0.0.1:443:443"
      - "8080:8080"  # "127.0.0.1:8080:8080"

    volumes:
      - /var/run/docker.sock:/var/run/docker.sock:ro
      - ./letsencrypt:/letsencrypt


  whoami:
    image: traefik/whoami

    labels:
      - "traefik.enable=true"
      - "traefik.http.routers.whoami.rule=Host(`whoami.${DOMAIN}`)"
      - "traefik.http.routers.whoami.entrypoints=websecure"

      - "traefik.http.routers.whoami.tls=true"
      - "traefik.http.routers.whoami.tls.certresolver=le"

    Y comentemos ahora las novedades en este fichero.

    Con

    - "--providers.docker=true"
- "--providers.docker.exposedbydefault=false"

    Traefik observa los contenedores mediante la API de Docker. Las reglas de publicación se especificarán utilizando labels. Y un contenedor solo será publicado si incluye - "traefik.enable=true". Esta configuración evita exponer accidentalmente servicios.

    Se crean dos puntos de entrada:

    - "--entrypoints.web.address=:80"
- "--entrypoints.websecure.address=:443"

    Recuerde que por convenio:

    web        → HTTP  → puerto 80
websecure  → HTTPS → puerto 443

    Gracias a 

    - "--entrypoints.web.http.redirections.entrypoint.to=websecure"
- "--entrypoints.web.http.redirections.entrypoint.scheme=https"

    Una petición http será redirigida a https, por lo que 

    http://whoami.alumno01.freemyip.com
=> será redirigida a:
https://whoami.alumno01.freemyip.com

    Se crea un resolver llamado le mediante:

    - "--certificatesresolvers.le.acme.email=${LE_EMAIL}"
- "--certificatesresolvers.le.acme.storage=/letsencrypt/acme.json"

    El nombre le es arbitrario. Podría llamarse de otra forma, pero debe coincidir con el utilizado posteriormente:

    - "traefik.http.routers.whoami.tls.certresolver=le"

    Ahora se le indica a Traefik que debe demostrar el control del dominio mediante DNS y que el proveedor de dominio será freemyip:

    - "--certificatesresolvers.le.acme.dnschallenge=true"
- "--certificatesresolvers.le.acme.dnschallenge.provider=freemyip"

    La credencial de FreeMyIP la utiliza Traefik para permitir que el componente ACME pueda modificar temporalmente los registros DNS necesarios. El token se obtiene del fichero de entorno .env

    environment:
  - FREEMYIP_TOKEN=${FREEMYIP_TOKEN}

    Durante las pruebas no debemos solicitar continuamente certificados reales. Let's Encrypt proporciona un entorno de pruebas. Por eso en nuestra configuración aparece:

    - "--certificatesresolvers.le.acme.caserver=https://acme-staging-v02.api.letsencrypt.org/directory"

    Los certificados emitidos por este entorno no son confiables para los navegadores, pero permiten comprobar que:

    • DNS-01 funciona.
    • FreeMyIP puede crear el TXT.
    • Traefik puede completar ACME.
    • el dominio está correctamente configurado.

    Important

    Durante el desarrollo utiliza siempre Staging. Pasa a producción solamente cuando la configuración funcione.

    3.2. Traefik Resolver¶

    En Traefik, cuando hablamos de un Certificate Resolver (resolutor de certificados), nos referimos al componente encargado de obtener y renovar automáticamente certificados TLS/SSL para los dominios de nuestras aplicaciones.

    Un Certificate Resolver configura cómo se comunica Traefik con una autoridad certificadora, como Let's Encrypt, y cómo demuestra que tenemos el control del dominio para el que solicitamos un certificado.

    Para realizar esta comprobación, Traefik puede utilizar distintos métodos:

    • DNS-01: Se demuestra el control del dominio creando un registro TXT específico en el DNS. No requiere que nuestro servidor web sea accesible desde Internet.
    • HTTP-01: Let's Encrypt comprueba que controlamos el dominio mediante una petición HTTP al puerto 80.
    • TLS-ALPN-01: La comprobación se realiza mediante una conexión TLS al puerto 443.

    4. Lanzar el proyecto¶

    Ejecutar, comprobar, y observar los logs con

    docker compose up -d
docker compose ps
docker compose logs -f traefik

    y busca mensajes relacionados con domain, solver, certificate o dns-01.

    4.1. Acceder a whoami¶

    Accede al servicio, por ejemplo:

    firefox https://whoami.alumno01.freemyip.com &

    El navegador mostrará una advertencia de certificado. Esto es loesperado porque todavía estamos utilizando Let's Encrypt Staging. Si continúas, deberías visualizar la respuesta del contenedor traefik/whoami.

    O Puede probar con curl

    curl -vk https://whoami.${DOMAIN}

    La opción -k permite continuar aunque el certificado de Staging no sea de confianza.

    Si quiere probar la redirección use la opción -L

    curl http://whoami.${DOMAIN}
curl -L http://whoami.${DOMAIN}
curl -kL http://whoami.${DOMAIN}

    4.2. Explicación¶

    Para obtener el certificado de whoami.alumno01.freemyip.com Let's Encrypt solicita demostrar el control del DNS. El proceso simplificado es:

    Traefik
   │
   │ solicita certificado
   ▼
Let's Encrypt
   │
   │ solicita desafío DNS-01
   ▼
Traefik / lego
   │
   │ usa FREEMYIP_TOKEN
   ▼
API de FreeMyIP
   │
   │ crea TXT temporal
   ▼
_acme-challenge.whoami.alumno01.freemyip.com

   │
   ▼
Let's Encrypt consulta el TXT
   │
   ▼
validación correcta
   │
   ▼
emisión del certificado

    Después de finalizar la validación el registro temporal puede eliminarse.

    5. Examinar el certificado¶

    Puede utilizar OpenSSL y ejcutar el comando

    openssl s_client \
  -connect 127.0.0.1:443 \
  -servername whoami.${DOMAIN} \
  </dev/null 2>/dev/null |
openssl x509 -noout -subject -issuer -dates

    Observe el subject (el dominio), que es un certificado de pruebas (staging) y el rango de fechas de validez del certificado.

    ¿Por qué -servername? en el comando

    Traefik puede gestionar múltiples sitios HTTPS sobre una única dirección IP y un único puerto 443. La opción -servername whoami.${DOMAIN} envía el nombre mediante SNI (Server Name Indication).

    SNI (Server Name Indication) es una extensión del protocolo TLS que permite que un servidor web aloje varios sitios HTTPS con distintos certificados, utilizando una única dirección IP y el mismo puerto 443. SNI permite resolver un problema que aparece antes del establecimiento de HTTPS: saber qué certificado presentar cuando varios dominios comparten la misma dirección IP y el mismo puerto.

    Puede tambien comprobar el contenido del fichero letsencrypt/acme.json donde se almacena por defecto la información de los certificados.

    $ cat letsencrypt/acme.json
...
    "Certificates": [
      {
        "domain": {
          "main": "whoami.midominio.freemyip.com"
        },
        "certificate": 
...

    6. Añadir otro servicio¶

    Añade al final de compose.yml:

      nginx:
    image: nginx:alpine
    labels:
      - "traefik.enable=true"
      - "traefik.http.routers.nginx.rule=Host(`nginx.${DOMAIN}`)"
      - "traefik.http.routers.nginx.entrypoints=websecure"
      - "traefik.http.routers.nginx.tls=true"
      - "traefik.http.routers.nginx.tls.certresolver=le"

    Aplica los cambios y comprueba

    docker compose up -d nginx
docker compose ps
docker compose logs -f traefik

    Traefik necesitará ahora un certificado para nginx.alumno01.freemyip.com. Puede comprobar en el log todo el proceso

    Info

    En esta parte de la práctica estamos trabajando con certificados individuales, uno para cada seervicio. Se pueden usar certificados wildcard puede cubrir ambos nombres. En esta rpáctica inicial no se cubre esa opción.

    Y para comprobar el nuevo servicio

    curl -vk https://nginx.${DOMAIN}
firefox https://nginx.TU-DOMINIO.freemyip.com &

    Puede ver el nuevo certificado:basta con reutilizar el comando previo y modificar el servername:

    openssl s_client \
  -connect 127.0.0.1:443 \
  -servername nginx.${DOMAIN} \
  </dev/null 2>/dev/null |
openssl x509 -noout -subject -issuer -serial -dates

    O visualizarlo el el fichero acme.json

    $ cat letsencrypt/acme.json 
{
  "le": {
    "Account": {
...

        "domain": {
          "main": "nginx.midominio.freemyip.com"
        },
        "certificate": ...

        "Store": "default"
...
$

    ¿Por qué funciona si el servidor no es público?

    Si se hubiese utilizado la validación con HTTP-01 Let's Encrypt necesita alcanzar el servidor mediante el puerto 80 y 443. En cambio, con DNS-01 Let's Encrypt necesita comprobar el DNS, no conectarse al servidor web.

    Por eso podemos tener resoluciones a una IP interna y aun así conseguir un certificado público válido.

    9. Anexos¶

    9.1. Seguridad¶

    La variable **FREEMYIP_TOKEN** debe tratarse como una contraseña. Por eso está almacenada en .env y .env aparece en .gitignore.

    Y sobre el fichero acme.json no muestres ni publiques su contenido. Contiene información sensible asociada a ACME y a los certificados.

    Por lo tanto ambos debe permanecer protegidos con permisos 600 e incluidos en .gitignore:

    Por otra parte Traefik necesita acceder a /var/run/docker.sock del host para descubrir los contenedores. En esta práctica lo montamos en solo lectura desde el punto de vista del contenedor con el sufijo :ro

    - /var/run/docker.sock:/var/run/docker.sock:ro

    Warning

    El acceso al socket de Docker es una capacidad sensible. En un entorno de producción deben analizarse cuidadosamente los riesgos y utilizarse medidas adicionales de aislamiento.

    Y por último, en la práctica se utiliza "--api.insecure=true". Esto permite acceder localmente a http://localhost:8080/dashboard/. Se utiliza por comodidad en un laboratorio y no es una configuración recomendable para producción.

    9.2. Posibles errores¶

    Puede terner problemas con el dominio, y este no resuelve a 127.0.0.1. Comprueba con:

    dig +short ${DOMAIN}
dig +short whoami.${DOMAIN}

    Si no vuelve a ejecutar:

    curl "https://freemyip.com/update?token=${FREEMYIP_TOKEN}&domain=${DOMAIN}&myip=127.0.0.1&verbose=yes"

    Puede modificar el servidor DNS que resuelve dig (en este caso Cloudflare o Google)

    dig @1.1.1.1 ${DOMAIN}
dig @8.8.8.8 ${DOMAIN}

    Otro posible problema es que el certificado no se genere. Comprueba los logs con

    docker compose logs traefik

    Debe buscar errores relacionados con certificate, dns, propagation, challenge o freemyip.

    Para mayor detalle, puede cambiar temporalmente el nivel de log de INFO a DEBUG:

    - "--log.level=DEBUG"  # "--log.level=INFO"

    y recrea Traefik con docker compose up -d

    Recuerde que como estamos usando el modo "staging" el navegador muestra un certificado no confiable, no es un error. Además si usa el comando curl deberá usar -k(y -L para la redireción)

    Otro error frecuente es que los puertos 80 o 443 están ocupados por contenedores previos u otros servicios.

    Puede comprobar antes de lanzar traefik si hay contenedores usando esos puertos:

    docker ps
docker ps -a

    o si hay otros servicios:

    ss -ltn | grep -E ':(80|443)\b'

    Otro posible problema es que Traefik no detecta el servicio que se añade. Comprueba las labels con:

    docker compose config

    y verifica especialmente si está habilitado el servicio y el nombre de las rutas y reglas:

    traefik.enable=true
traefik.http.routers.NOMBRE.rule
...

    9.3. ¿Qué es lego?¶

    Antes de ver que es lego, conviene recordar que que Let's Encrypt actúa como Autoridad de Certificación, y que el protocolo ACME (Automatic Certificate Management Environment) se utiliza para automatizar operaciones como demostrar el control de un dominio, solicitar certificados, obtenerlos, renovarlos o revocarlos. Y que Traefik necesita un cliente ACME para comunicarse con Let's Encrypt.

    lego es un un proyecto (independiente de Traefik) compatible con numerosos proveedores DNS. Es una biblioteca escrita en Go y con un cliente ACME. Traefik no necesita que instalemos lego por separado porque lo utiliza como biblioteca interna.

    Traefik utiliza internamente lego (no necesita que se instale) para las operaciones ACME. Cuando configura:

    - "--certificatesresolvers.le.acme.dnschallenge.provider=freemyip"

    Traefik selecciona el proveedor DNS de FreeMyIP implementado por lego. Por este motivo debemos proporcionar la variable FREEMYIP_TOKEN, que es la credencial utilizada por el proveedor freemyip de lego.

    El flujo simplificado durante DNS-01 sería

    Traefik
   │
   ▼
lego
   │
   │ ACME
   ▼
Let's Encrypt
   │
   │ challenge
   ▼
lego
   │
   │ API FreeMyIP
   ▼
TXT _acme-challenge.whoami....
   │
   ▼
Let's Encrypt
   │
   │ validación correcta
   ▼
certificado
   │
   ▼
Traefik

    Por lo tanto Traefik (usanddo lego) automatiza todo el ciclo de detectar, solicitar el dominio (gestionando el desafio), y luego almaacenar el certificado, utilizarlo y renovarlo si hace falta.
